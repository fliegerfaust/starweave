# Проверка баланса

Отвечает на вопрос «что правка сделала с балансом» числами из сима, а не на глаз.
Отчёт по-русски, шансы в процентах.

## 1. Что сравниваем

- **Текущее**: рабочая копия (ветка, на которой стоим, с незакоммиченными правками).
- **База**: первый аргумент, иначе ветка релиза, от которой ответвились (`release/<версия>`),
  иначе `main`. Если правок в `src/core` относительно базы нет (`git diff --stat <база> -- src/core`),
  сравнение не нужно: прогони только текущее и скажи это.
- **Режимы**: по умолчанию два прогона — полный (`npm run sim`) и новичок (`SIM_DEPTH=novice`).
  Если правка про конкретную систему, добавь её выключатель: мифы `SIM_MYTHS=0`,
  Резонанс `SIM_RESONANCE=0`, путь развилки `SIM_ROUTE=…` (все ручки — в шапке
  `tests/balance.sim.test.ts`). Дополнительные `SIM_*=…` из аргументов передай как есть.

## 2. Прогон

Сим идёт минуты: запускай в фоне и не дёргай вывод, пока не закончится.

- Текущее: `npm run sim` (и `SIM_DEPTH=novice npm run sim`), вывод в файл в scratchpad.
- База — во временной worktree в scratchpad, без порчи рабочей копии:
  `git worktree add --detach <scratchpad>/sim-base <база>`, туда симлинк `node_modules`
  из корня репозитория, прогон теми же командами с той же `SIM_RUNS`, потом
  `git worktree remove --force <scratchpad>/sim-base`.
- Сиды одинаковые (сим берёт `seed * 7919`), поэтому разница — от правки, а не от удачи.
- Если сим упал или не запустился, отчёт «НЕ ПРОВЕРЕНО» с ошибкой. Ничего не досчитывать на глаз.
- Полный прогон на 60 забегов идёт около 3 минут. Ошибка vitest `Timeout calling "onTaskUpdate"` после
  `✓ баланс > кривая целей` — шум долгого теста, не провал: цифры годные.
- Без `SIM_ROUTE` бот не ходит по развилкам (`шагов без ночи взято 0, мимо 0`): чтобы мерить развилки
  и Телескоп с Кометой, прогоняй с `SIM_ROUTE`.

## 3. Разбор

Отдай оба вывода агенту `balance-designer` (или разбери сам по его правилам):

- **Кривая**: по каждому ключу `<глава>-<ночь>` медиана `очки/цель`, доля ходов, смерти —
  было → стало. Стена — смертей заметно больше соседей; скука — `ходов` ниже ~50%.
- **Экономика**: ночей и лавок за забег, золото за забег, средняя глава, дар (взято / пропущено).
- **Системы**: мифы и Резонанс — частота и доля в очках, кто доминирует в списке.
- **Победы**: из скольких забегов.
- **Длина забега**: ночей за забег не больше +10% от базы (риск из `docs/RELEASE-0.7-DEPTH.md`).
- **Новичок**: до какой главы доходит первый забег.

## 4. Отчёт

```
## Баланс: <что меняли> (<ветка> против <база>, SIM_RUNS=<n>)

Вердикт: ЗДОРОВО | ЕСТЬ ВОПРОСЫ | КРИТИЧНО | НЕ ПРОВЕРЕНО

| Глава-ночь | очки/цель | ходов | смертей |   (было → стало)

Экономика: …   Системы: …   Победы: a/n → b/n   Новичок: …

Что заметно: 1–5 пунктов с числами.
Рекомендации: 1–3 по приоритету, с конкретными значениями констант.
```

Помни про ограничения: бот жадный и недобирает комбо, поэтому важна разница до и после, а не абсолют.
Если в `docs/ANALYTICS.md` или сводке есть живые данные по той же главе, сверь и скажи, где расходятся.

## 5. После

- Отчёт — в ответ. Если правка идёт по задаче трекера, кратко итог в `tt comment CG-… "…"`.
- Если Денис просит сохранить, положи в `docs/balance/<дата>-<тема>.md`.
- Константу с новой причиной сопроводи комментарием в коде с датой и числами сима,
  как у `ANTE_TARGETS` в `src/core/content/balance.ts`.

# Архитектура

Обновлено 21.10.2026 (0.5.10). Ревью перед 0.8 и техдолг — `docs/ARCH-REVIEW-0.8.md` в ветке
`release/0.8.0`.

## Стек и почему

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript (strict) | типы на правилах игры ловят ошибки баланса и событий |
| Сборка | Vite | мгновенный dev-сервер, маленький бандл, PWA без плагинов |
| Тесты | Vitest, Playwright | ядро тестируется без браузера; вёрстка — на 8 устройствах |
| Рендер | Canvas 2D + свой ECS | карточной игре хватает 2D; спрайты кэшируются в offscreen-канвасы; весь JS ~380 КБ (~130 КБ gzip) |
| Интерфейс | DOM-оверлей без фреймворка | меню, лавка, подсказки — текст; DOM даёт чёткий шрифт, доступность и CSS-анимации |
| Звук и графика | Web Audio и Canvas paths | всё генерируется кодом, ассетов нет |
| Сервер | Node 24 + SQLite, без зависимостей | события, сводка, оплата Stars; Node исполняет TypeScript сам |

## Ключевой принцип: логика мгновенна, вид — проигрыватель событий

Ядро применяет команду игрока целиком и возвращает **список событий** (`place`, `ignite`,
`clear`, `draw`, `nightWon`…). Презентер берёт их по очереди и превращает каждое в анимацию.
Отсюда:
- ядро не знает о времени и анимации — тесты быстрые, сим гоняет тысячи забегов;
- анимацию можно ускорить или пропустить, не трогая правила;
- прогноз на небе проигрывает настоящий `placeCard` на копии забега — правила не дублируются.

UI не меняет `RunState` напрямую — только через команды `App`. Экран выбирает один роутер
`App.route()` по `run.phase`.

## Знамения через хуки

`OmenDef` объявляет только нужные хуки (`effects.ts`): `modifyRules`, `onCardScored`,
`retriggers`, `onLineScored`, `onPlacementScored`, `onIgnite`, `onQuietPlacement`, `onBurn`,
`onNightStart`, `onNightEnd`. Конвейер вызывает их по порядку слотов (порядок важен, как у джокеров), затем
хуки Затмения, и пишет каждый вклад в шаги подсчёта. Новое Знамение — один объект в
`content/omens.ts` и строка в словарях.

## Сохранения и профиль

- Забег — `JSON.stringify(run)`. `deserializeRun` прогоняет цепочку миграций `RUN_MIGRATIONS`
  до `SAVE_VERSION` и проверяет структуру: фазу, карты, id Знамений, Затмений и неба. Битое,
  незнакомое или от более новой сборки — `null`, игра не падает.
- Профиль — цепочка `PROFILE_MIGRATIONS` и `sanitizeProfile`: каждое поле по типу, неверное —
  значение по умолчанию. Профиль новее сборки читается, но не перезаписывается: иначе старая
  сборка стёрла бы его в облаке.
- Новое поле или версия формата — шаг миграции и тест на JSON прошлой версии
  (`tests/migrations.test.ts`, образцы в `tests/fixtures/`).
- Реестры контента и товаров — без прототипа (`content/registry.ts`): id приходят из ссылок,
  сохранений и облака, `constructor` не должен быть Знамением.

## Площадки и покупки

Игра знает только интерфейс `Platform` (`src/platform/types.ts`): реклама, `payments`,
облачные сохранения, язык, пауза. Адаптер выбирается при запуске: Яндекс — флагом сборки,
Telegram — по параметрам запуска Mini App, иначе обычный веб.

`Payments` даёт `prices()`, `owned()`, `buy()`. Telegram Stars: счёт выставляет наш сервер,
игра открывает `WebApp.openInvoice`, оплату подтверждает вебхук бота. Яндекс — SDK площадки.
`Entitlements` хранит копию купленного и сверяется с площадкой. Каталог один на все площадки;
покупка раскрывается в то, что открывает. Силу игры не продаёт ничто.

## ECS

Минимальный ECS без зависимостей: сущность — число, компонент — типизированный токен с
хранилищем `Map<Entity, T>`, система — `update(world, dt)`. Через ECS живёт всё, что
двигается на канвасе: карты, частицы, всплывающие числа, фон. Правила в ECS **не** живут —
им нужен детерминизм ядра.
